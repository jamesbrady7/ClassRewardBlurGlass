班级激励助手 · 数据互通方案（讨论稿）
日期：2026-11-01
状态：仅方案讨论，尚未写任何同步代码。

============================================================
一、背景与约束
============================================================
1. 目前数据是单机本地 JSON（class_reward_data.json），换教室电脑后数据不互通。
2. 使用场景：同一位老师、不会两台电脑同时操作、教室固定电脑多台。
3. 教室电脑：有网络，但不建议安装软件；USB 口可用。
4. 老师自己的电脑容易坏，不能带去课堂，只希望在家里也能拿到数据。
5. 老师对数据损坏非常敏感：学生可能在上课途中拔掉 U 盘，历史上已发生过拔盘导致硬盘损坏的情况。
6. 数据粒度：需要保留每天、每次加减分的维度、类型、分值；不需要记录“哪台设备产生”。
7. 暂时不启用登录、不使用云、不考虑手机端（手机/云方案已讨论，工作量与不稳定因素较大，暂缓）。

============================================================
二、目标与非目标
============================================================
目标：
- 在不通网络、不登录、不在教室电脑安装软件的前提下，让数据在“教室电脑 A → 教室电脑 B → 家里电脑”之间安全流转。
- 数据始终至少有两份，拔 U 盘、U 盘损坏、单台电脑故障都不能造成全损。
- 不丢“最后一整节课”：最坏只丢失最后一次成功写入 U 盘之后的短时间。
- 研究数据可以一次性导出，不用一台台电脑手动收集。

非目标（当前阶段）：
- 不做云同步、不做账号系统、不做手机端。
- 不做两台电脑同时编辑的实时合并（只有一个使用者，顺序使用）。
- 不把 U 盘当作运行目录或唯一数据源。

============================================================
三、当前数据实现（已确认）
============================================================
- 存储：model/storage.py 的 StorageManager。
- 数据文件：单个 class_reward_data.json。
- 保存方式：先写 .tmp，再 os.replace 原子替换；单机不易写坏。
- 导入：controller.import_data() 是整份覆盖，不是合并。
- 积分记录 Transaction：有 timestamp / type / points / description / group_id，但没有独立 UUID。
- 结论：直接同步/覆盖这个 JSON 会丢数据；必须采用“版本化快照 + 选取最新有效版本”的方式，而不是两机合并。

============================================================
四、核心方案：单写者 + 本机工作副本 + U 盘保险库
============================================================
一句话：
  应用永远在本机磁盘上读写；U 盘只接收“带序号、带校验的版本化快照”。
  每次换电脑时，从 U 盘取最新有效快照，继续使用。

原则：
1. 任意时刻只有一台电脑写数据。
2. U 盘不是运行目录，不直接编辑 U 盘上的数据文件。
3. U 盘上的最新快照不覆盖旧快照；每次保存生成新文件。
4. 每次写入必须能校验（SHA-256），校验失败自动跳过，改用上一个有效版本。
5. 本机副本是安全缓冲；U 盘是随身保险库；第二份备份是最后防线。

============================================================
五、完整工作流
============================================================
到教室，插入 U 盘：
  1) 应用按“标记文件”识别保险库（不能写死盘符）。
  2) 扫描 snapshots，选“序号最高且 SHA-256 校验通过”的快照。
  3) 复制该快照到本机工作目录，作为本次工作副本。
  4) 在本机保留一份“本次开始前”的备份。

上课期间：
  1) 每次数据改动：立即保存到本机（原子写）。
  2) 每 30～60 秒：向 U 盘写一个新的版本化快照。
  3) 界面上显示“已写入保险库 / 可安全拔出”。
  4) 拔盘时：本机继续工作；U 盘写入失败不影响本机；插回后自动补写。

下课时：
  1) 写最终快照。
  2) 读回文件并校验哈希。
  3) 提示“数据已安全保存，可以拔出 U 盘”。

换到另一台电脑：
  1) 插入同一 U 盘。
  2) 取最新有效快照 → 复制到新电脑本机 → 继续。

异常场景：
  A. 学生拔盘：
     - 本机数据完整；最坏丢失最后一个快照间隔内的改动（可通过缩短间隔控制在 30 秒左右）。
     - 插回后自动补写；旧快照仍在，可回滚。
  B. 写 U 盘过程中断电/拔盘：
     - 只可能损坏本次尚未完成的临时文件/新快照；上一个完整快照不受影响。
     - manifest 只登记写入成功且校验通过的文件。
  C. U 盘物理损坏：
     - 需要第二块 U 盘轮换或网盘/另一地点的副本；软件无法救回彻底损坏的介质。
  D. 上次下课后没来得及写回 U 盘：
     - 本机 seq 比 U 盘新；应用提示用户，并把本机状态另存为新的恢复快照，保留 U 盘旧版本，不做覆盖。
  E. U 盘盘符变化：
     - 通过 vault.marker 识别，不写死盘符。

============================================================
六、U 盘目录结构
============================================================
ClassRewardVault/
  vault.marker                     标识文件（例如内容为 classreward.vault.v1）
  manifest.json                    快照清单
  snapshots/
    000123_20261101_104200.json    序号_日期_时间.json
    000124_20261101_104500.json
    ...
  exports/
    20261101_研究数据.csv
  recovery/                        可选：恢复/冲突副本
    ...

manifest.json 建议字段：
  {
    "vaultVersion": 1,
    "updatedAtUtc": "...",
    "snapshots": [
      {
        "seq": 123,
        "file": "snapshots/000123_20261101_104200.json",
        "savedAtUtc": "2026-11-01T02:42:00Z",
        "sha256": "...",
        "size": 123456,
        "appVersion": "4.3"
      }
    ]
  }

选择规则：
  - 只考虑 manifest 中登记且 SHA-256 校验通过的文件。
  - 取 seq 最大者。
  - 不依赖文件修改时间（不同电脑时钟可能不准）。

写入规则：
  1) 写临时文件（如 snapshots/.tmp_xxx）。
  2) flush/fsync（确保真正落盘）。
  3) 计算 SHA-256。
  4) 改名为正式快照文件名。
  5) 原子更新 manifest（写临时 + 替换）。
  6) 清理超出保留数量的旧快照（保留最近 N 个/最近 N 天）。
  任何一步失败：不更新 manifest，旧快照继续可用。

============================================================
七、本机数据路径与便携运行
============================================================
- 本机工作副本建议：
    %LOCALAPPDATA%\ClassRewardHelper\class_reward_data.json
  不再放在应用目录/U 盘。
- 本机备份目录建议：
    %LOCALAPPDATA%\ClassRewardHelper\backups\
- 教室电脑没有 Python：需要便携版 exe（PyInstaller 等打包），从 U 盘运行；数据写本机，快照写保险库。
- 应用需要识别“自己所在的 U 盘”或按标记文件搜索所有盘符。
- 便携版第一次运行需要测试：
    · 教室电脑是否允许运行 U 盘上的 exe；
    · SmartScreen/杀毒是否拦截；
    · 是否有写 %LOCALAPPDATA% 的权限；
    · U 盘的删除策略是否为“快速删除”。

============================================================
八、第二份备份与家里电脑
============================================================
- 强烈建议两块 U 盘轮换：一块在教室用，一块放在家里；每天/每周轮换一次。
- 或在家里把保险库复制到网盘/另一个移动硬盘，作为第三份。
- 家里电脑的角色：读取保险库、导出 CSV、做分析；不作为唯一数据源。
- 不能把“容易坏的家用电脑”当作唯一备份。

============================================================
九、研究数据导出
============================================================
现有 Transaction 已包含时间、类型、分值、描述（维度），足够做研究。
建议新增导出 CSV，每行一条积分记录：
  班级, 学号, 姓名, 日期时间, 维度/描述, 类型(加分/扣分/兑换/使用/盲盒), 分值, 小组
不需要“设备来源”字段。
导出文件可写入 U 盘 exports/ 目录，回家直接分析。

============================================================
十一、暂不做的内容
============================================================
- 云同步、账号登录、实时多端编辑。
- 手机端 / PWA / 原生 App（已评估：工作量大、不确定因素多，暂缓）。
- 复杂 CRDT/合并算法（单写者顺序使用，当前不需要）。
- 两台电脑同时编辑同一份数据的冲突合并。

============================================================
十二、需要确认的问题
============================================================
1. 教室电脑是否允许直接运行 U 盘上的 exe（SmartScreen/杀毒/组策略）？
2. 是否愿意准备第二块 U 盘做轮换备份？
3. 自动写 U 盘的间隔：30 秒 / 60 秒 / 5 分钟？（越短越安全，U 盘写入越频繁）
4. U 盘当前的删除策略是否为“快速删除”？
5. 家里电脑只用于查看/导出，还是也要继续记分？
6. 学校/家长对学生数据存放在 U 盘是否有额外要求？
7. 便携版 exe 由哪台机器构建、如何测试教室电脑兼容性？

============================================================
十三、建议的实施顺序
============================================================
第 1 步：便携版 exe + 本机工作副本 + U 盘保险库 + 版本快照 + 校验 + 安全拔出提示。
第 2 步：自动定时快照 + 拔盘/插回处理 + 恢复提示 + 第二份备份流程。
第 3 步：研究数据 CSV 导出。
第 4 步（可选，未来）：如需手机/云，另做独立方案，不在当前范围。

============================================================
十四、重要提醒
============================================================
- 永远不要把唯一一份数据放在 U 盘上运行。
- 永远不要在 U 盘上直接编辑 class_reward_data.json；只写带序号的快照。
- 第二份备份不是“可选优化”，而是 U 盘物理损坏时的唯一保障。
- 本文档只是方案，当前代码尚未实现上述保险库逻辑。
